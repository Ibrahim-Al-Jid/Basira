## 12.1 · مجموعة القبول

مجموعة `marsad-phase12-holdout-1` مستقلة عن fixtures تطوير المحللات. فيها مدخلات اصطناعية دفاعية من HTML وHAR وملفات المصدر والإعدادات وOpenAPI وZAP المحفوظ، مع أمثلة نظيفة ومدخل معطوب. اتثبتت التوقعات على مستوى **معرّف القاعدة ومسار الملف والسطر**، واتثبتت أولوية مرجعية للحالات المناسبة قبل القياس. بصمة المجموعة في [manifest.sha256](../tests/fixtures/phase12/manifest.sha256). استخدمنا OWASP Benchmark كمرجع لطريقة بناء الحالات الموجبة والسلبية. المجموعة الحالية لمدخلات مرصد ونتيجتها تخص هذه المجموعة. [OWASP Benchmark](https://owasp.org/projects/benchmark)

حالة التنبيه المرجعية استخدمت نفس إصدار Jinja2 المعروف في اختبار تركيب OSV السابق مع مسار جديد. القياس يشمل أدوات التشغيل الحالية، وتجارب Semgrep وTrivy موثّقة في مرحلة الأدوات. [قبول الأدوات](PHASE10-TOOLS.md)

| عتبة التقييم المثبتة | القيمة |
|---|---:|
| Precision وRecall للمحللات المجمعة على المواضع | 90% أو أكثر لكل مقياس |
| سقف p95 للقواعد الأساسية | 300 ms |
| سقف p95 للقواعد والمحللات المجمعة | 22,000 ms |
| سقف p95 لزمن إضافة بوابة الموديل التجريبية | 150 ms |
| تحسّن إصابة الأولوية الأولى | 10 نقاط مئوية أو أكثر |
| تغيير الأدلة أو نتائج مكررة أو إخفاقات غير متوقعة | صفر |
| طلبات البوابة في الفحص الواحد | طلب واحد كحد أقصى |

المقارنة بين القواعد المسجلة، ونفس القواعد مع Gitleaks وOSV-Scanner، ثم نفس الأدلة مع تشغيل عقد الإثراء بردود محاكية. التقييم يفصل تطابق قاعدة من تطابق موضعها، ويفصل الأثر الحتمي للمحللات من تغيير ترتيب العرض. توقيت المحللات من حاوية بلا شبكة ومحدودة الموارد، ووقت البوابة المحاكية خاص بالبروتوكول المحلي. [ممارسات تقييم الأنظمة](https://developers.openai.com/api/docs/guides/evaluation-best-practices)

أعد القياس من جذر المشروع بنفس الصورة والحزمة. العدد ثلاثة تكرارات لكل حالة على أدوات التحليل. زمن الإثراء يقيس إضافة البوابة بعد اكتمال التحليل.

```powershell
$fixtures = (Resolve-Path tests/fixtures/phase12).Path
$runner = (Resolve-Path backend/phase12_evaluation.py).Path
docker run --rm --network none --read-only --tmpfs "/tmp:size=64m,noexec,nosuid,nodev" `
  --memory 400m --cpus 1 --pids-limit 64 --cap-drop ALL --security-opt no-new-privileges:true `
  --mount "type=bind,source=$fixtures,target=/phase12,readonly" `
  --mount "type=bind,source=$runner,target=/srv/marsad/backend/phase12_evaluation.py,readonly" `
  marsad-platform:phase12-release python -m backend.phase12_evaluation `
  --manifest /phase12/manifest.json --profile bundled --repetitions 3
```

## 12.2 · سلوك الإثراء

| المسار | صحيح / زائد / فائت | Precision | Recall | p50 / p95 |
|---|---:|---:|---:|---:|
| القواعد الداخلية | 7 / 1 / 3 | 87.5% | 70% | 5.69 / 43.56 ms |
| القواعد مع Gitleaks وOSV-Scanner | 9 / 1 / 1 | 90% | 90% | 5.58 / 10333.43 ms |
| نفس المحللات مع إثراء محاكى | 9 / 1 / 1 | 90% | 90% | 0.24 / 11.74 ms إضافة بعد التحليل |

اشتغلت ١١ حالة كما هو متوقع واترفض مدخل JSON المعطوب. المحللات أضافت موضعَي دليل صحيحين. الاختلاف المتبقي في `HTML-17` بين موقع النموذج في السطر ٢ في المرجع وموقع حقل كلمة المرور في السطر ٣ في المحرك. اتسجل كموضع زائد وآخر فائت حسب المطابقة المثبتة. الناتج الكامل يوضح المفاتيح والبصمات والعتبات لكل حالة. [نتائج القياس الخام](phase12-results.json)

أصاب كل من الترتيب المحلي والترتيب المحاكى أولوية الحالتين المعلّمتين. تحسن الأولوية ٠ نقطة مئوية، أقل من العتبة المثبتة. اختبارات المهلة والرد المعطوب والإبطال حافظت على الأدلة والتغطية، والتكرارات الكاملة كانت صفر. المزوّد المحاكى سجل ١٢ طلبًا خلال التكرارات، بحد طلب واحد للفحص، و١٢٠٠ توكن مدخل و٢٤٠ مخرج ضمن بيانات الاختبار. تكلفة المزوّد الفعلية غير مقاسة.

الإثراء اختياري لكل فحص، ومحتاج اتصالًا مُصرّحًا للمشروع. الترتيب المقترح يتطبق في الواجهة وPDF عندما العقد يقبل الرد كاملًا. الإصلاح والموقع والدليل والتغطية تفضل من المحرك. عند فشل الرد، العرض يستخدم ترتيب الشدة المحلي. مهلة الشبكة تخلّي عدد الاستدعاءات غير متاح في التقرير لو الخادم ما قدرش يؤكد النتيجة. ترتيب الموديل الحالي يشمل معرّفات سجل القواعد الأساسية، وباقي النتائج تظهر بترتيب محلي بعد المقترحات.

تجربة المزوّد تقيس الالتزام بالعقد ورفض القواعد المخترعة أو الردود الناقصة، وبتستخدم عدادات توكنز اصطناعية لو الرد قدّمها. الشرح والإصلاح الحاليين من القواعد المحلية.

بوابة التشغيل التلقائي لمزوّد فعلي تحتاج عينة مستقلة أوسع، وتحسن الأولوية الأولى بعشر نقاط مئوية، وصفر تغييرات للأدلة، وطلبًا واحدًا على الأكثر، وتكلفة فعلية بحد 0.01 دولار للفحص المثْرى وزمن إضافة p95 بحد ٣ ثوانٍ. التكلفة والوقت الفعليين يفضلوا غير متاحين لحد تشغيل تقييم مع مزوّد مُعدّ ومصرّح له.

## 12.3 · عزل البيئة والرجوع للإصدار

قبول اللقطات محليًا يستخدم ZIP. تفعيل GitHub الفعلي يحتاج إعداد GitHub App وتخصيص تثبيت للمؤسسة. اختبارات GitHub تستخدم بروتوكولًا محاكيًا للتثبيت والتنزيل وتثبيت SHA والإبطال. [إعداد GitHub](PHASE11.md#اتصالات-github)

- لاختبار تعطيل محلّل، غيّر `MARSAD_SOURCE_ADAPTERS` في ملف البيئة للبيئة المقصودة وأعد تشغيل الخدمات المشتركة. القيمة الفارغة تعطّل المحللات المضافة. ابدأ فحصًا جديدًا بعد التغيير، وتحقق من خطة الفحص والتغطية. تحمل الفحوصات السابقة إصدارات الأدوات المثبّتة وقت إنشائها.
- قبل التفعيل، احفظ PostgreSQL وSQLite وبيانات تهيئة التشغيل، واحفظ مفتاح تشفير الموديلات الخاص بالبيئة منفصلًا. تحقق من الأعداد وبصمة التقارير على نسخة مستعادة. صورة Phase 11 السابقة هي `marsad-platform:phase11-release`. Phase 12 يستخدم نفس رأس Alembic `platform_evidence_links_0011`.
- الرجوع بعد تغييرات مستقبلية للمخطط يتطلب صورة متوافقة مع نسخة قاعدة البيانات. اختبر الاستعادة والرجوع على مشروع Compose منفصل. افصل تقييم صورة التطبيق عن صلاحية الحسابات أو اتصالات المزوّد الخارجي.

تشغيل القبول المكرر يبدأ من Compose معزول على المنفذ 8776 باسم `marsad12-qa`. عيّن `MARSAD_PHASE12_QA_CONTAINER=marsad12-qa-app-1` وشغّل `python tests/browser_phase12.py`. المتغير `MARSAD_PHASE12_CHECK_RANKING=1` يضيف تحقق العرض بترتيب اصطناعي، و`MARSAD_TEST_ARTIFACT_DIR` يحفظ نسخ PDF وJSON التجريبية. اختبر مسار المصادر عبر `python tests/browser_source_intake.py`، ومرّر اختبار `tests/container_phase45.py` لخدمة التطبيق في بيئة الاختبار.

نجح بناء Docker و٢٠١ اختبار Python وثماني حالات فرعية. تشغيل CLI الاختياري متاح عبر حاوية القياس، واتخطى في مجموعة Python العامة. Chromium اختبر الحساب والثيم والدعوات والعزل والكيبورد والتقارير بالعربي والإنجليزي على ٣٢٠ و٥٦٦ و١٢٨٠ px. اتراجع عرض PDF للغتين بما فيه RTL وطابقنا القاعدة والملف والسطر والعداد، واتحقق تصدير SARIF بمخطط OASIS. استعادة PostgreSQL على نسخة منفصلة حافظت على بصمة التقريرين و١٥ جدولًا بسياسات RLS إجبارية، والصورة السابقة قرأت التقريرين عبر دور التطبيق. نسخة SQLite حافظت على التقارير الخمسة. نجح إلغاء مهمة في PostgreSQL بعد حجزها ورفض نشر النتيجة المتأخرة، واختبار تعطيل المحللات شغّل الفحص الأساسي وأبقى الكتالوج ١٠٠ قاعدة.

اتفعّل الإصدار `marsad-platform:phase12-release` على [مرصد المحلي](http://127.0.0.1:8765/dashboard) يوم ٢١ نوفمبر ٢٠٢٦. بعد التفعيل اتطابق عدد الحسابات والمشاريع والفحوصات وبصمة التقارير، ورأس الترحيل فضل `platform_evidence_links_0011`. GitHub ظهر غير مفعّل في البيئة المحلية حسب الإعداد الحالي.
