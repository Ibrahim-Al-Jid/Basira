# تصميم بصيرة

## المشاريع الشخصية

يُفعّل المسار الشخصي بإعداد `BASIRA_PERSONAL_PROJECTS=1` بعد ترحيل PostgreSQL ومراجعة ملكية المشاريع. الجلسة هي مصدر هوية الحساب. قوائم المشاريع وعمليات العرض والتعديل والحذف تقارن المالك بالحساب، وكل مسار لفحص أو نتيجة أو تقرير تابع للمشروع يبدأ بنفس التحقق. عزل بيانات الفحص في PostgreSQL يجمع نطاق المشروع الفعلي مع سياسة RLS مقيّدة تتطلب تطابق المالك. تُضبط الهوية في نفس المعاملة، وتنتهي بانتهائها. عامل المهام يقرأ المالك من سجل المشروع قبل فتح نطاقه، ويحافظ على الـlease الحالية بوصفها شرط نشر النتيجة. [سياسات PostgreSQL المقيدة](https://www.postgresql.org/docs/18/sql-createpolicy.html) · [إعدادات المعاملة](https://www.postgresql.org/docs/18/functions-admin.html) · [صلاحيات الموارد في OWASP](https://api-security.owasp.org/editions/2023/en/0xa1-broken-object-level-authorization/)

المشاريع الجديدة تستخدم معرّف نطاق داخليًا خاصًا بالحساب لاستمرار المفاتيح المركبة الحالية. الكيانات ومسارات التوافق القديمة تُراجع للإزالة ضمن المرحلة P18 في [الخطة](PLAN.md). في المسار الشخصي تُعرض تقارير المشاريع الموثّقة لمالكها، وتتوقف واجهات المختبر والدعوات وإدارة المؤسسات.

في المسار الشخصي، إعدادات OpenRouter ومفتاحه المشفّر تخص الحساب. عرض الموديلات يستخدم قائمة OpenRouter الخاصة بالمستخدم. عند اختيار الإثراء لفحص معين، البوابة تتحقق من مالك المشروع والـlease ونسخة الاتصال، ثم ترسل للموديل معرّفات القواعد وأعداد النتائج لترتيب الأولويات. التحليل والأدلة والتغطية مصدرها محرك الفحص المحلي. [دليل البيانات](ERD.md) · [الترحيل والتشغيل](PLATFORM.md#تفعيل-المشاريع-الشخصية--phase-13)

شريط المشاريع يستخدم روابط تنقّل عادية. على الموبايل يظهر زر يعلن حالة الفتح، والإغلاق بـEscape يرجّع التركيز له. اختبار المتصفح يغطي الواجهة العربية الضيقة والتنقّل بالكيبورد. [نمط التنقل في WAI-ARIA](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/examples/disclosure-navigation/)

## استقبال المصادر الشخصية

واجهة بدء الفحص تعرض ZIP وGitHub وWebsite URL. كل مدخل يراجع ملكية المشروع ونسخة السياسة والحصص ومفتاح التكرار قبل التحليل. يُحفظ المصدر المقبول كـ`SourceSnapshot` ببصمة SHA-256، وتثبت سياسة الفحص بنفس معاملة إدخاله للطابور. يصف `TargetProfile` أنواع الملفات والملفات المستبعدة وبصمة المحتوى النصي، أو حدود واستجابة رصد HTTPS. يعرض التقرير نوع المصدر والتغطية الملائمة.

ZIP وGitHub يشتركان في فحص الأرشيف والجرد والتحليل المحلي. يتدرج رفع ZIP إلى ملف مؤقت محدود، ثم يُراجع SHA-256 بعد حفظه وقراءته من S3/MinIO عند تهيئة التخزين. تُحذف نسخة الحجر بعد التحقق، ويحتفظ طابور الفحص بالمدخل المقبول حتى الحالة النهائية أو انتهاء المهلة. تظل الحدود ٢ ميجابايت للأرشيف، و٨ بعد الفك، و١ للملف، و٢٠٠ عنصر. تُرفض الأرشيفات المتداخلة والتكرار والروابط الرمزية والأنواع الخاصة والضغط المتجاوز للحد. [Python ZIP](https://docs.python.org/3.13/library/zipfile.html#decompression-pitfalls) · [S3 checksums](https://docs.aws.amazon.com/AmazonS3/latest/userguide/checking-object-integrity.html)

اتصال GitHub مستقل عن جلسة تسجيل الدخول إلى بصيرة. تبدأ الجلسة تفويض GitHub App باستخدام state أحادي الاستخدام وPKCE. صلاحية قراءة التثبيت والمستودع تُراجع من GitHub عند كل استيراد. يتحول الفرع أو معرّف النسخة إلى SHA ثابت قبل طلب الأرشيف، ويُنزل من codeload من دون إرسال رمز API إليه. يمرّر Intake اللقطة وبصمتها للمحلل. يبقى رمز GitHub المشفّر داخل مسار التفويض، ويمنع إبطال الاتصال إدخال لقطات جديدة. [تفويض GitHub App](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/generating-a-user-access-token-for-a-github-app) · [صلاحيات التثبيت](https://docs.github.com/en/rest/apps/installations) · [أرشيف المستودع](https://docs.github.com/en/rest/repos/contents#download-a-repository-archive-zip)

جامع الموقع يرسل GET واحدًا لكل صفحة HTTPS عامة معتمدة تحديدًا للمشروع، بحد ثلاث صفحات من نفس الأصل. يتحقق من كل عناوين DNS المستلمة قبل تثبيت عنوان الاتصال، ويتحقق TLS من اسم المضيف. يرفض التحويلات، ويحد حجم الاستجابة عند ٢٥٠٬٠٠٠ بايت. يحوّل الاستجابة إلى دليل HAR مختصر برؤوس مختارة بعد التنقيح، وسمات حماية الكوكيز، ومعلومات إصدار TLS، وأعداد النماذج والروابط. محتوى الصفحة وأسماء الكوكيز وقيمها خارج البيانات المحفوظة. فحوصات HAR التي تتطلب سجل رؤوس كامل تُعامل التغطية على أنها محدودة. [ضوابط SSRF في OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html) · [تشغيل المدخلات](PLATFORM.md#تشغيل-مدخلات-الفحص--phase-14)

## سياسة تنفيذ الأدوات

تُثبت معرّفات المحللات وإصداراتها في سياسة الفحص عند جدولة المهمة. يتحقق عامل التحليل من الخطة وإصدار القواعد عند التخطيط وقبل التنفيذ، ويعرض قرار كل أداة وسبب اختيارها أو تخطيها. التقارير الجديدة تسجّل إصدار الأداة وحالتها ومدتها بعقد `basira-tool-result-1`. تظل التقارير السابقة قابلة للقراءة.

سجل الأدوات يحمل الآن maintainer ومصدر الإصدار ونوع فحص الجاهزية وصيغ المدخلات وحدود الذاكرة وعدد الأنوية لكل محلّل. الوسيط يتحقق من إصدار الأداة المثبّت بأمر `--version` قبل كل تنفيذ، ويرفض أي إصدار مختلف أو غير مثبّت قبل استهلاك مهلة التشغيل. فهرس تنبيهات npm يُبنى وقت بناء الصورة من أرشيف OSV الرسمي المثبّت ببصمة SHA-256، ويُختزل إلى سجلات الحزم الموجودة فعليًا في اللقطة قبل تمريرها إلى OSV في وضع عدم الاتصال. تجاوز ٢٠٠٠ سجل أو ١٦ ميجابايت ينتج تغطية جزئية بسبب ثابت، ولا يُسقط نتائج PyPI المتاحة. Semgrep وTrivy يظلان في حالة `shadow` ومعطّلين.

تشغّل بوابة الأدوات أمرًا ثابتًا لـGitleaks مع التنقيح الكامل، وأمرًا ثابتًا لـOSV-Scanner في الوضع المحلي مع تعطيل حل التبعيات. يتحقق العامل من مواقع المدخلات والمخرجات داخل مجلده المؤقت، ويرفض خيارات التشغيل ومتغيرات البيئة خارج القائمة المعتمدة. إخفاق أداة خارجية يظهر في التغطية، ويحتفظ التقرير بنتائج الأدوات اللي نجحت. إعداد Compose يعزل شبكة خدمة التحليل ويستخدم نظام ملفات للقراءة فقط خارج المساحات المؤقتة والمجلد المخصص لتبادل المهام.

## الوكلاء وحقائق اللقطة

مسار التنفيذ عقد حتمي من خمس عقد: `orchestrator → planning → analysis → validation → reporting`. كل عقدة تقيد بأداة محددة من صلاحيات دورها، وتسجل اسمها والمدة والدور في `task_runs`. يربط العقد `basira-agent-workflow-1` بصمة المصدر وبصمة الجرد النصي وبصمة خطة الأدوات وبصمة الأدلة ومعرّف الفحص. أي نتيجة خارج الملفات المقروءة أو خارج حدود السطر أو ببصمة غير مطابقة أو منسوبة لأداة غير مختارة تُرفض قبل التقرير، حتى لو كانت البصمة نفسها صحيحة.

المستشار الاختياري استدعاء واحد محدد: الخادم يرسل معرّفات القواعد وأعدادها وأدوارًا مرجعية (`e1`…) وأسماء أدوات مسموحة فقط، دون مسارات ملفات أو محتوى أو أسرار أو معرّفات حساب. يقبل الخادم الرد كاملًا أو يرفضه كاملًا إذا خرج عن القائمة المعتمدة، ولا يستطيع إنشاء نتيجة أو تغيير دليل أو خطورة. عند غياب المزوّد أو فشل التحقق يبقى التقرير الحتمي كما هو.

نقطة الاستئناف تُحفظ بعد التحقق في `project_scans.analysis_checkpoint` بربط يضم بصمة المصدر والمعرّفات ونسخة السياسة والمشروع والمالك. الكتابة والاسترجاع محكومان بـlease نشط وملكية المشروع وسلامة المدخل، ويُمنع استبدال الأدلة بعد التحقق بمقارنة إسقاط منقّح. عند الإنهاء أو انتهاء مدة المصدر يُمسح الـcheckpoint. ذاكرة المراجعة تُسترجع من نفس المالك والمشروع والبصمة والنطاق خلال ٩٠ يومًا وبحد ٢٠ تصنيفًا، وتحمل حالة المراجعة السابقة لا تعليق المستخدم ولا أدلة جديدة. [تفاصيل المرحلة](PLAN.md)

## نموذج التهديد (ذاتي)

بصيرة تقرأ ملفات غير موثوقة وتعرض جزءاً من حقائقها على نموذج لغوي، فهي نفسها هدف. الضوابط الحالية والاختبارات التي تثبتها في `backend/test_self_security.py` و`backend/test_advisor.py`:

| التهديد | الضابط | الاختبار |
|---|---|---|
| تعليمات داخل الملف الممسوح موجهة للنموذج | المسار الإنتاجي يرسل أعداداً ومعرّفات وقواعد فقط، لا نص الملف ولا مساره | تعليمات في كل حقل نصي لا تصل إلى طلب النموذج |
| نموذج ينفذ تعليمات محقونة (أداة غير معتمدة، مفتاح زائد، نص بدل JSON) | ردّ النموذج يُرفض كله ويبقى التقرير الحتمي | ردود محقونة تُرفض ويبقى التقرير كما هو |
| وكلاء التجربة تقرأ نص الملف | النص في رسالة المستخدم فقط، وأداتان للقراءة فقط، وأداة مجهولة تُرفض | الوكيل المطيع لا ينتج نتائج ولا يشغّل أداة |
| SSRF عبر عنوان المزود المخصص | https فقط، المنفذ 443، بلا بيانات اعتماد، العنوان يُحلّ ويجب أن تكون كل العناوين عامة، ويُعاد الفحص عند كل طلب | أشكال عناوين محلية وخاصة وأرقام بصيغ بديلة وإعادة ربط DNS |
| تحويل HTTP إلى عنوان داخلي | لا تتبّع للتحويلات | الطلب يُرسل بدون تتبّع ويفشل 502 |
| تسرب مفتاح المزود | مفتاح مشفّر مربوط بالمؤسسة والجيل، يُرسل في الترويسة لا في العنوان، ويُقنَّع | مفتاح مغيَّر أو لمؤسسة أخرى لا يُفك، ولا يظهر في رسائل الخطأ |
| ZIP خبيث (مسار هروب، رابط رمزي، ملف مشفر، أرشيف متداخل، قنبلة ضغط، حجم مصرّح به كاذب) | `zip_texts`: مسارات آمنة، 200 عنصراً، 1 MB للملف و8 MB بعد الفك، نسبة ضغط أقصاها 200، رفض الروابط والأرشيفات المتداخلة | `backend/test_upload_and_export.py`: 29 اختباراً؛ حذف فحص `..` أو نسبة الضغط يكسر الاختبارات |
| JSON خبيث (تداخل عميق، مفاتيح مكررة، NaN) | `read_object` يرفضها برسالة عامة | نفس الملف |
| محتوى ضار داخل التقرير المصدَّر | HTML يهرّب كل نص مع `Content-Security-Policy: default-src 'none'`، واسم الملف المصدَّر ثابت أو من معرّف التقرير | تقرير فيه وسم HTML يظهر مهرّباً، ومعرّف تقرير فيه سطر جديد أو علامة اقتباس يعطي 404 بدون ترويسات إضافية |
| محتوى ضار داخل PDF المصدَّر | `printable` يحذف محارف التحكم والتنسيق (بما فيها NUL وعلامات الاتجاه) ويقصّ الحقل إلى 450 حرفاً، والنص يُرسم كحروف لا ككائنات PDF | `backend/test_upload_and_export.py`: نص فيه `/JS` و`/OpenAction` و`/URI` وNUL وESC و3000 حرف لا يظهر في الملف أي كائن نشط (JavaScript وLaunch وURI وEmbeddedFile)؛ الاختبار كشف أن NUL كان يمر فعلاً وأُصلح |

فحص ذاتي بأدوات خارجية، 27 نوفمبر 2026: gitleaks 8.21.2 على تاريخ git (58 commit) لم يجد تسريباً؛ semgrep 1.187.0 (قواعد python وjavascript وgithub-actions) أعطى نتيجتين من نوع `avoid-sqlalchemy-text`؛ bandit 1.9.4 على كود الخلفية بدون الاختبارات أعطى 10 نتائج متوسطة؛ pip-audit على الحزم المثبتة: لا ثغرات معروفة. راجعنا كل نتيجة متوسطة يدوياً ولم نجد استغلالاً: أسماء الإجراءات والجداول تأتي من ثوابت في الكود لا من مدخل المستخدم، وعلامات `?` في استعلام npm تُبنى من العدد فقط، وكل `urlopen` يستعمل عنوان https ثابتاً، والمسارات المؤقتة في تجربة الكشف هي قيم افتراضية لأداة تُشغَّل يدوياً. تشغيل gitleaks على الملفات بدون git وجد ملفين، وكلاهما ملف `.pyc` مولَّد من اختبارات تحتوي مفاتيح وهمية عمداً (غير متتبَّع في git). لم تُضَف هذه الأدوات إلى CI بعد.

غير مغطى بعد: لا شيء من قائمة P22 سوى إضافة الأدوات الخارجية إلى CI. تصدير SARIF خارج النطاق: رفضه المالك في 27 نوفمبر 2026.

### الخمس أدوار وصلاحياتها

دلوقتي كل دور عقدة فعلية في LangGraph، وسجل القواعد في `backend/rules.py` بيفهرس الدليل داخل Python قبل تشغيلها. التحليل بيتشعب إلى فرع أو فرعين. الإثراء بالموديل اختياري، ومسموح باستدعاء واحد محدد لكل فحص عند تفعيله. في الفحص المحلي ما فيش استدعاءات للمزوّد. الخادم يثبت النتائج من السجل، ويسجل مصدر القرار ويستخدم القالب المحلي عند تعطل التلخيص.

| الدور | الموجود في الكود | عقد التصميم وصلاحيته |
|---|---|---|
| Orchestrator | يختار split/combined من الأعداد وملخص سابق محدود | ينسّق انتقال الحالات اللي السياسة مثبتاها. يقرأ حالة التشغيل والميزانية، ويكتب قرار التوجيه وأحداثه. |
| Planning | يرتب مجموعات جاهزة ويقدّمها لـLangGraph | يقرأ إمكانات المدخل وإصدارات القواعد المسجلة والسياسة، وينتج خطة بأسماء الأدوات المعتمدة وأسباب التخطي. الخادم يتحقق من اكتمال واختيارات الخطة قبل التنفيذ. |
| Analysis | يقارن مطابقة الفرع المحلية بترشيح الموديل عند تفعيله | يستقبل نتائج محللات محلية محددة في الخطة. يقترح ترتيب أو تفسير، ويسجل أدلته باستخدام المعرّفات. العامل يملك تنفيذ الـAdapters وفق سجل ثابت. |
| Validation | يثبت كل دليل مطابق محليًا | يتحقق حتميًا من نسخة القاعدة وانطباقها والدليل والموقع، ويوحّد النتائج. النوع السياقي يطلب مراجعة بشرية. كتابة حالة النتيجة تحتاج سياسة التطبيق. |
| Reporting | يولّد ملخصين من الحقائق المحلية، والموديل يقدر يرتّب أولويات الإصلاح | يقرأ نتائج ثابتة منقّحة وتغطية الفحص. القالب يضمّن الأعداد والأدلة، ومصدر ترتيب الأولويات يظهر في التقرير. |

في التصميم المستهدف، الخادم بيتحقق من الصلاحيات عند كل إجراء. أدوار LangGraph تتبادل معرّفات وبيانات مقيدة بالمخطط، وعندها صلاحيات كتابة أحداث الدور وبياناته المشتقة فقط. الأسرار تحت إدارة خدمة الهوية والمزوّد، وإدارة العضويات لطرف بشري مصرح. يتعامل الـworker مع البيانات المحلية على إنها نص غير موثوق بدون تشغيل ملفات أو كود أو أوامر مشتقة من المدخل. المدخل الخام، أسماء خاصة، التوكنات وHAR الخام يُحجبوا عن النموذج والسجلات. يُسجل لكل دور القرار والإصدار والمدة وحالة الاستدعاء ومصدره `system/model` من غير حفظ prompts أو ردود خام.

### عقد الأدوات

كل adapter له `tool_id` وإصدار، مدخلات مسموحة، قائمة قواعد وإعدادات موثقة، سقف وقت وذاكرة وحجم مخرجات، وإشارة نجاح أو فشل. يسترجع `rule_id` وإصدارها، موضع الدليل، درجة ثقة، نص مختصر محجوب، وتوصية. عنصر `observed` يصف حقيقة مدعومة. عنصر `review_required` يصف مؤشر سياقي. عند غياب ملفات مطلوبة، القاعدة تسجل سبب عدم الانطباق أو التخطي. حدد hashes لنسخ الأدوات وبيانات advisories، وثبّت الإصدارات. شغّل تحديث قاعدة advisories في عملية إدارة منفصلة عن العامل. المعرّفات والتركيبات تُسجل على السيرفر والموديل يستقبل ملخصات محدودة. يمنع runner أوامر النظام العامة، وتثبيت حزم المشروع، وتشغيل build أو hooks.

### أنواع الذاكرة

| النوع | التنفيذ وملكية الكتابة | ما يُسترجع |
|---|---|---|
| Working | حالة مرتبطة بـscan ID والمحاولة، مع checkpoint خادمي مُنقّح ومحمي بـlease. | نتيجة التحليل الحتمي اللازمة لإكمال النشر دون إعادة معالجة المصدر. |
| Episodic | سجل الفحوصات والتقارير في PostgreSQL. | مقاييس الفحوصات السابقة في نفس المشروع، ويظهر الفرق لو نسخ السياسات مختلفة. |
| Semantic | سجلات مرجعية مُراجَعة مع المصدر والإصدار وتاريخ الاعتماد، من مسؤول محتوى. | إرشادات معالجة صالحة ومصرح بها، مع المرجع في التقرير. |
| Procedural | Tool Registry وقواعد وإصدارات وسياسات ثابتة يديرها المسؤول. | تعريف القاعدة أو الإجراء والإصدار المثبّت للفحص. |
| Project | بيانات المشروع والأهداف وسياسات ونطاق الإدخال يكتبها صاحب صلاحية. | خصائص المشروع وسياساته فقط. |
| Finding | نتيجة ثابتة ووقائع من الفحوصات وأحداث حالة وتعليقات منفصلة. | تاريخ الدليل وحالة المعالجة. تعليقات المستخدم محتوى غير موثوق. |

قرارات الاسترجاع تستخدم مفاتيح المؤسسة والمشروع المستخرجة من عضوية متحققة؛ سجلات المنهج العامة تجي من registry منفصل. اقترح انتهاء المصدر المرفوع بعد سبعة أيام مبدئيًا عند تفعيل تخزينه، مع احتفاظ التقارير وفق سياسة المشروع ومراجعة المتطلبات قبل التشغيل الحقيقي. الحذف المنطقي يوقف الوصول فورًا ويجدول الحذف من التخزين ونسخ الفهرس. التطوير المحلي يستخدم بيانات اختبار.

### الوصول والمتانة

- Owner يدير المؤسسة والعضويات والاحتفاظ. Admin يدير المشاريع وسياساتها وأذوناتها. Analyst يضيف مصدرًا ويبدأ فحصًا ويعلّق ويغيّر حالة نتيجة، وViewer يقرأ ويصدّر التقارير. Analyst وViewer يحتاجوا إذن صريح لكل مشروع، وتتعطّل الأذونات فور إبطال العضوية. التطبيق يفرض النطاق على القراءة والكتابة والملفات والمهام والتصدير. سجل audit للأحداث الإدارية، ومفاتيح ملكية مركّبة وسياسات RLS. عزل بيانات المختبر المجهول عن الحسابات، وفرض صلاحية الجلسة من الخادم.
- مهمة الفحص تستخدم معرف idempotency ضمن المؤسسة، وسجل outbox في نفس معاملة إنشاء المهمة، وlease محددة لكل محاولة. واجهة الأحداث تقرأ snapshot ثم أحداثًا متزايدة للاستئناف. العامل يكتب الفحص النهائي والأدلة والحالة في معاملة مشروطة بالمحاولة الفعالة. لو اتوقف المزوّد، يستمر المسار الحتمي وتُسجّل حالة الإثراء. اعمل ضبط معدل وحصص حسب العضو والمشروع، وتصنيف أخطاء وسقوف للتوازي وتكلفة المزوّد.
- تعامل مع اسم الملف كبيانات للعرض، وكشف نوع وترميز وحجم المحتوى، وارفض المسارات الخارجة والروابط الرمزية والأرشيفات المتداخلة عند توسيع الإدخال. أظهر الأدلة كنص. لا تسمح للملف يحدد إضافة أو command أو عنوان اتصال. عزل تصدير HTML عن التطبيق وتحقق الإذن وقت التنزيل. [OWASP File Upload](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)
