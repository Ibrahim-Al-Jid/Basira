# Phase 15 | سجل الأدوات والتنفيذ المحلي المعزول

[خطة التطوير والقبول](plan-19-phases.md#phase-15) · [الخط المرجعي Tools-only](../phase15-tools-baseline.json)

عامل التحليل يستقبل نسخة محلية من الملف اللي اختاره المستخدم. في استيراد GitHub، خدمة الاستيراد تثبّت الـCommit أولًا وتمرّر الأرشيف إلى نفس العامل. العامل يشتغل من غير شبكة، على نظام ملفات للقراءة فقط، ومع مساحة مؤقتة للتنفيذ، وذاكرة 400 ميجابايت وCPU واحد. سجل النتيجة يفرّق بين الأداة المختارة أو المستبعدة، وحالة التنفيذ وسببه، ومواضع الأدلة اللي نجح إثباتها.

## قاعدة بيانات npm

صورة `scanner-npm` تبني فهرس SQLite من نسخة OSV الرسمية المثبّتة بتاريخ ٢٢ نوفمبر ٢٠٢٦ وبصمة SHA-256 موضحة في Dockerfile. الفهرس يحفظ سجلات التنبيهات الأصلية حسب اسم الحزمة المتأثرة. وقت الفحص، يستخرج العامل سجلات أسماء الحزم الموجودة فعلًا في اللقطة، ثم يمرر أرشيفًا صغيرًا إلى OSV عشان يطابق الإصدارات بنفس المحرك. البيانات المتوفرة في الفهرس تغطي كل الإصدارات المذكورة في سجلات الحزم المختارة. [دليل OSV للتشغيل المحلي](https://google.github.io/osv-scanner/usage/offline-mode/)

اختيار مجموعة npm يتوقف لو تعدّت ٢٠٠٠ سجل أو ١٦ ميجابايت من البيانات الأصلية. في الحالة دي تظهر نتيجة التغطية الجزئية بسبب ثابت. نتائج PyPI المتاحة تفضل محفوظة لو فهرس npm مش متاح أو لو المجموعة تعدّت الحد. نتيجة فحص الملفات لا تحتاج تنزيل حزمة أو تشغيل كود من المشروع.

## التشغيل والتحقق

```powershell
docker compose -p marsad-local -f compose.yaml -f compose.local.yaml --env-file .env.local --profile model up -d --build
```

صورة `marsad-platform:local` تخص خدمات التطبيق، وصورة `marsad-platform:scanner-local` تخص عامل التحليل. في تشغيل `--no-build` جهّز الصورتين مسبقًا. تحديث بيانات التنبيهات يحصل في بناء صورة جديدة بمصدر وبصمة معروفين، وبعدها يُستبدل العامل بعد تحقق النسخة. بيئة فحص المشروع تستخدم البيانات المتوفرة في الصورة.
