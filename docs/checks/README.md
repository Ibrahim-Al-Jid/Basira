# كتالوج ١١٤ فحص دفاعي

إصدار `basira-static-3` فيه ١١٤ قاعدة. تحت هنا القواعد الخمسين الأصلية، والقواعد الخمسين المضافة في [فحوصات HTML وHAR الإضافية](web-extra.md) و[فحوصات التبعيات والإعدادات الإضافية](config-extra.md)، والأربعة عشر فحصًا للكود المصدري في [فحوصات الكود المصدري](source-code.md). سجل المحرك الداخلي متاح عبر `GET /api/catalog`. انطباق القاعدة يعتمد على النوع والسياق والسياسة، وبعض النتائج تستدعي مراجعة بشرية. [تشغيل المشاريع](../PLATFORM.md)

## A. إعدادات HTML والموارد الخارجية · ١٠

| ID | الفحص | دليل التطابق والانطباق |
|---|---|---|
| http-script | سكربت عبر HTTP | عنصر script له src بعنوان HTTP صريح، مع السطر. |
| http-form | نموذج يرسل إلى HTTP | form له action بعنوان HTTP صريح، مع السطر. |
| cdn-integrity | سكربت من CDN معتمد بدون SRI | host ضمن CDN المعروفة وintegrity فارغة أو غائبة. |
| HTML-04 | stylesheet خارجي من CDN معتمد بدون SRI | عنصر link stylesheet يطابق سياسة CDN بلا integrity. |
| HTML-05 | قيمة SRI بلا بصمة بالأشكال المدعومة | integrity موجودة وقيمتها غير فارغة على مورد مؤهل وبلا أي digest صالح شكليًا؛ التطابق مع محتوى المورد غير متاح من HTML وحده. |
| HTML-06 | override للإرسال إلى HTTP | عنوان HTTP صريح في formaction لعنصر إرسال صالح، مع سطر العنصر. |
| HTML-07 | iframe يتحمل عبر HTTP | src صريح لـiframe في مستند متوقع تقديمه عبر HTTPS. |
| HTML-08 | stylesheet تتحمل عبر HTTP | href صريح لـlink stylesheet في مستند متوقع تقديمه عبر HTTPS. |
| HTML-09 | توجيه meta إلى HTTP | meta refresh له وجهة HTTP صريحة في مستند متوقع تقديمه عبر HTTPS. |
| HTML-10 | iframe خارجي مع sandbox غائب | iframe من أصل خارجي غير معفى حسب سياسة المشروع، بدون sandbox. يحتاج مراجعة سياق. |

## B. سياسة المتصفح والاستجابات المحفوظة · ١٠

| ID | الفحص | دليل التطابق والانطباق |
|---|---|---|
| WEB-01 | HSTS مفقود أو متوقف | رؤوس HTTPS محفوظة لاستجابة نهائية من أصل مُدار، مع غياب الحقل أو max-age يساوي صفر حسب السياسة. |
| WEB-02 | CSP نافذة غائبة | وثيقة HTML متوقعة تحت سياسة CSP، والرؤوس كاملة ولا يوجد رأس enforcing أو meta صالح للغرض. |
| WEB-03 | سياسة CSP تسمح بسكربتات inline على نطاق واسع | السياسة الفعالة تسمح بـunsafe-inline؛ تحقق من تداخل السياسات والـnonce/hash قبل تسجيل المؤشر. |
| WEB-04 | سياسة CSP تسمح بالتقييم الديناميكي | التوجيه الفعال يسمح بـunsafe-eval في سياسة نافذة حسب دلالة المتصفح؛ يحتاج مراجعة. |
| WEB-05 | حماية التأطير غائبة | وثيقة غير مخصصة للتضمين بلا frame-ancestors نافذ أو X-Frame-Options صالح. |
| WEB-06 | X-Content-Type-Options مفقود أو غير صالح | استجابة تطبيقية من snapshot كامل، والقيمة لا تحقق nosniff. |
| WEB-07 | سياسة Referer توسّع تسريب المسار خارج الأصل | وجود unsafe-url صراحةً في رأس فعال لوثيقة خاضعة للسياسة. |
| WEB-08 | استجابة خاصة تسمح بتخزين مشترك | المسار موسوم كخاص في سياسة المشروع ومعه Cache-Control عام أو s-maxage موجب؛ يحتاج مراجعة. |
| WEB-09 | كوكي جلسة من غير Secure | رأس Set-Cookie لاسم كوكي مُعرّف كجلسة، وSecure غائبة في snapshot HTTPS. استخدم الاسم وعلامات السمات فقط. |
| WEB-10 | كوكي جلسة من غير HttpOnly | كوكي جلسة مصنّفة حسب سياستها يلزم حمايتها وHttpOnly غائبة. |

## C. التبعيات وسلسلة التوريد · ٨

| ID | الفحص | دليل التطابق والانطباق |
|---|---|---|
| DEP-01 | إصدار مباشر مطابق لتنبيه منشور | package وإصدار مثبت وadvisory ID صالح في بيانات OSV المؤرخة، وأصل dependency مباشر. |
| DEP-02 | إصدار انتقالي مطابق لتنبيه منشور | نفس معيار التنبيه مع dependency انتقالية فقط ومسارها في lockfile. بناء مباشر يغلب عند تكرار نفس المكوّن والتنبيه. |
| DEP-03 | Lockfile مفقود | مشروع يُنشر كتطبيق وmanifest مدعوم، وsnapshot كامل، والـlockfile المتوقّع مفقود حسب نوع المدير. |
| DEP-04 | مصدر تبعية صريح عبر HTTP | تبعية غير محلية معرفة بمصدر HTTP في ملف الحزم أو القفل. |
| DEP-05 | Git dependency على مرجع متغيّر | تبعية Git في manifest/lockfile بلا commit مثبت حسب نوع الملف وسياسة المشروع؛ يحتاج مراجعة. |
| DEP-06 | حزمة خارجية بلا digest | مدير وتنسيق قفل يدعمان بصمة لحزمة registry، وحزمة تنطبق عليها السياسة بلا بصمة. |
| DEP-07 | registry غير مصرح | مضيف تبعية registry مثبت في lockfile ويخرج عن allowlist إعدادها المشروع، مع استبعاد مصادر HTTP المُسجّلة تحت DEP-04 لنفس الموضع. |
| DEP-08 | npm lockfile يتعارض مع manifest | مجموعة المتطلبات المباشرة المصرّح بها لا تتطابق مع metadata الجذر في lockfile المدعوم. يتم التحليل بدون تثبيت الحزم. |

## D. الحاويات والبنية التحتية · ١٠

| ID | الفحص | دليل التطابق والانطباق |
|---|---|---|
| INF-01 | تشغيل container بصلاحية root صراحةً | Dockerfile في المرحلة النهائية يحدد root/UID 0 صراحةً؛ غياب USER يحتاج دليل من الـbase image قبل الحكم. |
| INF-02 | base image من غير digest ثابت | مرجع FROM خارجي في Dockerfile قابل للبناء، بدون digest وفق سياسة التثبيت. |
| INF-03 | حاوية Kubernetes privileged | manifest مُقدم وفيه privileged صريحة للحاوية. |
| INF-04 | Pod يستخدم شبكة المضيف | hostNetwork مفعّل للـPod حسب سياسة العزل. |
| INF-05 | Pod يشارك PID namespace للمضيف | hostPID مفعّل في manifest حسب سياسة العزل. |
| INF-06 | Pod يركب مسار من المضيف | hostPath مذكور بلا استثناء مُعرّف بالمشروع؛ يحتاج مراجعة للغرض والوجهة. |
| INF-07 | Kubernetes يعطي قدرات Linux إضافية | capabilities.add تتضمن قيمة محظورة بموجب سياسة المشروع. |
| INF-08 | K8s يسمح برفع الصلاحيات صراحةً | allowPrivilegeEscalation مفعّل صراحة لحاوية غير privileged؛ privileged يُسجل تحت INF-03. |
| INF-09 | S3 بلا public-access-block مطلوب | إعدادات Terraform المعروفة في snapshot كامل والـblock المطلوب مفقود أو معطل في المستوى الفعال المتاح. يحتاج مراجعة لو إعداد الحساب خارج اللقطة. |
| INF-10 | DDL لجدول مستأجرين بلا سياسة عزل مطلوبة | migrations SQL مدعومة لمشروع يشترط RLS، وفي snapshot المخطط إشارة مؤكدة لجدول tenant بلا ENABLE أو سياسة حماية. لو الـDDL ديناميكي تُطلب مراجعة. |

## التحقق والتجميع

النتائج في التقرير تتجمع حسب معرّف القاعدة وتحتفظ بكل مواضع الدليل. الربط بين إعداد التطبيق ورصد من أصل مختلف يحتاج إثبات إن الدليلين لنفس التطبيق المنشور. في لقطة HTTP ناقصة، الفحوصات المبنية على الغياب تتوقف عند البيانات المتاحة. [OWASP ASVS 5.0](https://owasp.org/www-project-application-security-verification-standard/) · [OSV Schema](https://ossf.github.io/osv-schema/) · [Trivy Misconfiguration](https://trivy.dev/docs/latest/scanner/misconfiguration/)

### مراجع تصنيف منتقاة

| معرّف بصيرة | المرجع | إمتى تستخدمه |
|---|---|---|
| `http-form` وHTML-06 | [CWE-319](https://cwe.mitre.org/data/definitions/319.html) | لو مراجعة السياق أثبتت إن وجهة HTTP تنقل بيانات حساسة. |
| WEB-09 | [CWE-614](https://cwe.mitre.org/data/definitions/614.html) | لو الرصد يخص كوكي جلسة حساسة في HTTPS وعلامة Secure غائبة. |
| APP-01 وAPP-02 | [CWE-798](https://cwe.mitre.org/data/definitions/798.html) | لو الدليل يخص اعتمادًا مضمنًا في التطبيق. يفضل التحقق من شكل الدليل والسياق من غير تجربة سر حي. |

القواعد اللي بتطبق سياسة فريق، زي إلزام lockfile أو تثبيت أداة CI، تحتفظ بمعرّف بصيرة وسياسة المشروع. مدى انطباق المعيار على التطبيق يتحدد من الدليل ونطاق المراجعة.
