# مرصد | مرجع المشروع

المستخدم بيدخل كود HTML أو بيشغّل العينة، ويربط حساب OpenRouter، ويختار الموديل قبل الفحص. الهدف هو مراجعة إعدادات السكربتات والنماذج بالأدلة، ومراقبة قرارات الوكلاء، وتنزيل التقرير بالعربي أو الإنجليزي. هذا الملف هو المرجع المعتمد للنطاق والقرارات والخطة والقبول والتشغيل.

## المراحل ١–٣ · سجل النسخة الأولى



| المرحلة | المسؤول | المتطلبات | المخرجات ومعيار القبول |
|---|---|---|---|
| ١. عقد الفحص | محرك الوكلاء | كود HTML محلي وعينة معلومة النتائج | لكل وكيل مدخل وإجراء ومخرج وأداة وذاكرة. تحقق آلي من اكتشافات العينة ومن المدخلات النظيفة والفارغة |
| ٢. بيئة التشغيل | الواجهة وخدمة النموذج | عقد الفحص ومخطط طلب التلخيص | تشغيل الأدوار الخمسة من المتصفح، عرض الأدلة والمؤشرات وتصدير التقرير. مفتاح النموذج مؤقت، والتلخيص اختياري |
| ٣. القبول والتسليم | منسّق المشروع | تكامل الواجهة والمحرك والخدمة | تشغيل الاختبارات المحلية وتجربة المسار من المتصفح، ثم بناء نسخة الاستضافة والتحقق من النشر |

يقتصر التحليل على الإعدادات الظاهرة في نص HTML المدخل. تُقاس جودة الاكتشاف على العينة المرجعية، وتُقاس مدة التنفيذ وعدد الأدلة في كل تشغيل. لا توجد بيانات حقيقية لقياس الدقة العامة أو تكلفة النموذج.

اكتمل ربط المراحل. الاختبارات تغطي القواعد ومزوّد التلخيص البديل وحفظ النتائج عند فشله. أظهر تشغيل العينة في المتصفح خمس مراحل مكتملة وثلاث مطابقات بلا نتائج إضافية. الاتصال الحقيقي يعتمد على مفتاح المستخدم.


## المراحل ٤–٦ · التوسعة

| المرحلة | المسؤول والاعتمادات | الناتج | دليل القبول |
|---|---|---|---|
| ٤. عقد النموذج والوكلاء | فريق المحرك والخدمة، بعد تثبيت نطاق القواعد الثلاث | كتالوج الحساب من OpenRouter مع تمييز النماذج المجانية والمدفوعة، وخريطة LangGraph تستهلك الموديل المختار | اختبار نموذج بديل يثبت استدعاءات كل دور، وفرعين متوازيين يلتقيان قبل التحقق، وفشل صريح عند رفض المزود |
| ٥. مساحة تشغيل React | فريق الواجهة والتقارير، بعد عقد الأحداث والتقرير | خريطة تتكون من أحداث الخادم، وسجل مختصر، وذاكرة وتقارير قابلة للتنزيل باللغتين | مطابقة العقد للأحداث، واسترجاع تقرير مكتمل، وفتح نسختي HTML مع الاتجاه الصحيح والنص والدليل |
| ٦. التكامل والتسليم | منسق المشروع، بعد تكامل React وFastAPI | مدخل تشغيل واحد، قاعدة SQLite، تعليمات وأدلة قبول | بناء Vite، اختبارات Python، تجربة مسار الواجهة، ثم تشغيل التطبيق الفعلي على نفس الأصل |

## مسار التنفيذ والذاكرة

| الدور | المدخل | الإجراء والأداة | المخرج |
|---|---|---|---|
| المنسّق | أعداد العناصر وإحصاء آخر فحص للجلسة إن وُجد | يسأل النموذج عن فصل مراجعة السكربتات والنماذج أو جمعهما | قرار التوجيه |
| التخطيط | قرار التوجيه ومجموعات العمل المتاحة | يرتب النموذج المجموعات، ويتحقق الخادم من شمولها، ثم يوزّع LangGraph المهام | فرع أو فرعان للتحليل |
| التحليل | خصائص HTML مستخرجة محليًا | يقرأ النموذج الخصائص ويرشح معرفات القواعد المطابقة لكل فرع | ترشيحات منفصلة تجتمع في حالة الرسم |
| التحقق | الترشيحات وأعداد الأدلة | يراجع النموذج الترشيحات ويقيّد الخادم النتائج بالأدلة المطابقة من المصدر | ملاحظات برقم السطر، ووصف الخصائص المطابقة بعد حجب العنوان والسمات الحساسة، والشدة، والإصلاح |
| التقارير | توزيع الملاحظات المؤكدة وتعليمات الإصلاح | يكتب الموديل ملخصين، ويضيف الخادم البيانات والأدلة في قالبين قابلين للتنزيل والطباعة | تقرير محفوظ ونسختان بالعربي والإنجليزي |

ذاكرة العمل هي حالة LangGraph التي تحمل قرارات التشغيل ونتائج الفروع. تحتفظ الجلسة بآخر ١٠٠ تقرير مكتمل، ومدة صلاحية ملف تعريف الجلسة ٣٠ يومًا. ذاكرة الإجراءات هي تعريفات القواعد والعقد ومساراتها في الكود. الذاكرة المستمرة هي التقارير المكتملة في SQLite المرتبطة بملف تعريف جلسة المتصفح. يستخدم المنسق عدد ملاحظات الفحص السابق كسياق محدود. إعادة فتح نفس المتصفح تتيح استرجاع التقارير طالما بقيت الجلسة والقاعدة متاحتين.

## حدود البيانات والقياس

يحلل FastAPI نص HTML على الخادم. استدعاءات OpenRouter تحتوي على بيانات بنيوية وأعداد وقرارات محددة، والدليل المحفوظ هو وصف مختصر للوسم يحجب عنوان الوجهة والقيم الحساسة ويحتفظ برقم السطر. يُستخدم المفتاح للتحقق وللطلبات في ذاكرة التشغيل. كل عقدة تستدعي النموذج المختار عبر LangChain، ويمكن لاختلاف الإجابات أو حدود المزود أن يغيّر النتيجة أو يفشل الفحص.

العينة المرجعية فيها ثلاث ملاحظات محددة عند الأسطر ٥ و٦ و٩. النجاح يتطلب تطابق القاعدة والسطر لكل منها وصفر ملاحظات زائدة. يُعرض قياس العينة عند تطابق المصدر المرجعي، ومع كل فحص يُسجَّل عدد القواعد والملاحظات واستدعاءات النموذج والمدة. نطاق النسخة يقتصر على سكربتات HTTP ونماذج HTTP وغياب integrity لسكربتات من ثلاث شبكات CDN.

## تشغيل التطبيق

من مجلد sentinel على Windows باستخدام Python 3.13 وNode.js:

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements-dev.txt
npm --prefix frontend ci
npm run build
npm start
```

افتح http://127.0.0.1:8765 واختر الإعدادات لربط OpenRouter. للقبول الآلي استخدم `npm test`. يستعمل التشغيل المحلي React المبني من `frontend/`، والخدمة في `backend/main.py`، والرسم في `backend/graph.py`. المراحل ١–٣ أعلاه توثّق النسخة التجريبية السابقة.

للاستضافة على خادم يدعم Python أو Docker، يحتاج مجلد بيانات SQLite إلى قرص مستمر، وتحتاج طلبات النتائج إلى دعم البث التدريجي. مثال لتشغيل الحاوية محليًا:

```sh
docker build -t marsad .
docker run -p 127.0.0.1:8000:8000 -v marsad-data:/srv/marsad/data marsad
```

استضافة النسخة الأولى تستخدم JavaScript Worker. النسخة الجديدة تستخدم عملية FastAPI طويلة التشغيل. نشرها على الإنترنت يتطلب وجهة استضافة تدعم هذه العملية وقرص البيانات.

## سجل القبول · ١٨ نوفمبر ٢٠٢٦

اكتملت المراحل ٤–٦ محليًا. نجح بناء React واختبارات المحرك والخدمة والتكامل. شغّل اختبار المتصفح نفس حزمة React وFastAPI وLangGraph وLangChain، مع بديل HTTP مؤقت لردود OpenRouter وقاعدة منفصلة. اختير الموديل من الإعدادات، واشتغل مسار الفرعين بستة استدعاءات. أظهر التقرير ثلاث مطابقات من ثلاث وصفر نتائج إضافية ونسختين للتنزيل. تحققت الاختبارات أيضًا من اختلاف مسار الفرع الواحد، وعزل تقارير كل جلسة، ورفض المفتاح غير الصالح. أمكن قراءة الكتالوج العام الحي، وتجربة استدلال حي تتطلب مفتاح صاحب الحساب. لم يُنشر إصدار Python على الاستضافة القديمة، ولم تُختبر صورة Docker على هذا الجهاز.
