# قرارات توسعة مرصد بعد Phase 6

مراجعة مقترحي **Vulnerability Taxonomy, Tool Integration, Benchmark Strategy & UX Redesign** و**AI-Powered Web Security Platform** على النسخة المنشورة في `755e63b`. المستند ده بيوضح قرارات المنتج والأدلة اللي أدت ليها. ترتيب التنفيذ والقبول والتبعيات في [الخطة الموحدة](../work/plan.md#توسعة-المنتج-بعد-phase-6)، وحالة الإصدار الحالي في [قبول 2.3](RELEASE.md).

## قرارات تجربة الاستخدام

| المقترح | القرار |
|---|---|
| Landing ثم دخول ولوحة مشاريع | اعتمد في [Phase 8](../work/plan.md#phase-8). وصف البداية المقترح «راجع إعدادات موقعك وكودك من الأدلة اللي بتقدمها». زر «ابدأ» يفتح رحلة المشروع، و«استكشف الإمكانيات» ينزل للقسم اللي يشرح المدخلات المدعومة. تجانس العربية والإنجليزية وتفضيل تقليل الحركة قبل إضافة الأنيميشن. |
| التنقل وموضع الأدوات | اعتمد Dashboard، Projects، Scans، Findings، Reports، Settings، وزر New Scan. Coverage تبويب في التقرير ومدخل تقني من الإدارة. Models وTools وCatalog تحت Settings للإدارة، وتفاصيل الوكلاء تظهر داخل التشغيل. لوحة أدوات كاملة تبقى مفيدة عند تشغيل أدوات متعددة. |
| New Project وNew Scan | المشروع ممكن يجمع Website asset وSource snapshots. ابدأ بملف ZIP أو HTML أو HAR أو إعدادات، واعرض الرابط كمعرّف ومصدر ربط. المعالج خمس خطوات من الهدف للدليل والصلاحية ثم سياسة الفحص والمراجعة والتشغيل. المستخدم يشوف الاختيارات المتاحة وأسباب التعطيل. الاستنتاج من manifest أو lockfile يساعد يحدد نوع المشروع، والاختيار النهائي بسياسة حتمية. |
| Demo وسجل التقارير | العينة اختيار صريح في Demo، وإعادة الضبط ترجع لمدخل فاضي. التقرير المقصود من مشروع يظهر في نفس نقطة الدخول مع سياق صلاحياته. روابط الإصدار السابق تظل قابلة للفتح. نقل تقرير مجهول لمشروع إجراء ترحيل يحتفظ بإثبات الملكية. |
| Progress والتقرير | عداد الوقت والمراحل الفعلية والنتائج الأولية حسب الأحداث، وحالات انتظار وتشغيل وجزئي وفشل وإلغاء. التقرير يجمع ملخص النطاق، النتائج والدليل والتأثير والإصلاح والمراجع، التغطية، التاريخ والمقارنة والتصدير. Severity وConfidence وReview State منفصلة. أضف Critical وInformational بعد اختبار توافق القيم القديمة ومحول SARIF. HTML/JSON/SARIF موجودة حسب نوع التقرير. PDF مؤجل لما بعد قبول قالب التقرير وقراءة العربية. |
| Models وKnowledge | إدارة الموديل في إعدادات المشرف مع الحالة والميزانية ونسخة الإعداد، وخيار بسيط لنوع الإثراء عند الحاجة. قواعد الاختيار والأذونات خارج الموديل. ذاكرة تشغيل الوكلاء تبقى في تفاصيل التنفيذ، ومعرفة المشروع المنشورة تظهر بعلامة مصدر وتاريخ انتهاء وسياسة معزولة للمشروع. |
| أمثلة منتجات السوق | استفد من علاقة المشروع بالمصدر في Snyk، ومن ربط نتيجة الكود بالموضع وحالة المعالجة في GitHub، ومن تنظيم الأدلة في Burp. تصميم مرصد يوحّد الرحلة حوالين المشروع ونطاق الأدلة. [Snyk Projects](https://docs.snyk.io/scan-fix-and-prevent/scan-with-snyk/snyk-projects.md) · [GitHub code scanning alerts](https://docs.github.com/en/code-security/code-scanning/managing-code-scanning-alerts/about-code-scanning-alerts) · [Burp Organizer](https://portswigger.net/burp/documentation/desktop/tools/organizer) |

فحص المصدر الحالي في `backend/artifact_review.py` و`backend/platform_api.py` له حد ٢ مليون بايت ويستخدم أربعة أنواع مدخلات. `Platform.jsx` يجمع إدارة المشروع والفحص والسياسة والذاكرة. `main.jsx` يشغل المختبر أولًا، و`Reports.jsx` فيه فرع للمختبر وفرع للمشروع. التشابه يسمح بفصل المكونات تدريجيًا مع إبقاء عقود الخادم والروابط. استخدم React/Vite الحاليين، وCSS logical properties وتوكنات مشتركة، واختبر لوحات RTL/LTR وحالات التحميل والخطأ وإعادة العرض. إضافات router أو state library أو ترحيل TypeScript تُدرس عند ظهور مشكلة ملموسة. [WCAG 2.2](https://www.w3.org/TR/WCAG22/) · [Playwright accessibility](https://playwright.dev/docs/accessibility-testing)

## التصنيف والتغطية

| الكيان | دوره في مرصد |
|---|---|
| OWASP Top 10:2025 وAPI Top 10:2023 | تجميع للتوعية ومراجعة تغطية مجالات المخاطر، مع معرّف الإصدار. [OWASP Web](https://top10.owasp.org/2025/0x00_2025-Introduction/) · [OWASP API](https://owasp.org/API-Security/editions/2023/en/0x00-header/) |
| WSTG 4.2 وASVS 5.0.0 | تصنيف طرق التحقق ومتطلبات الضوابط. خزّن المراجع بمعرّف وإصدار، واعتمد المراجع الأحدث فقط بعد مراجعة الربط. [WSTG](https://owasp.org/projects/web-security-testing-guide) · [ASVS](https://owasp.org/projects/asvs) |
| CWE | تعريف عائلة الضعف أو السبب، بمراجع متعددة عند الحاجة. [MITRE CWE](https://cwe.mitre.org/about/index.html) |
| CVE وGHSA وOSV | رقم نشرة لمشكلة محددة في مكوّن. النتيجة تتطلب مكوّنًا ونظام حزم وإصدارًا ونطاق تأثر ومصدرًا ووقت قاعدة البيانات. ادمج الأسماء البديلة بعد توحيد الهوية. [OSV Schema](https://ossf.github.io/osv-schema/) |
| قاعدة مرصد وأداة وحالة مرجعية | القاعدة لها معرّف ثابت وعقد دليل. الأداة تطبقها على مدخل مؤهل. الحالة المرجعية لها نتائج متوقعة ومقامات قابلة للحساب. |

الأكواد D01–D18 أدناه تصنيف مقترح. يبقى الـ١٠٠ معرّف الحالي زي ما هو. مثال التوافق `HTML-17` مع مجاله الحالي ومع أكثر من مجال تصنيف لو الدليل يسمح. يُضاف ربط متعدد بدل إعادة تسمية القواعد. اسم المجال في واجهة التغطية مفيهوش ادعاء بفحص كل العائلات المذكورة تحته.

| المجال المقترح | حدود المدخل والقرار |
|---|---|
| D01 التفويض وعزل المؤسسات | مراجعة كود وسياسات وأدلة اختبارات يقدّمها الفريق. صلاحيات الكائن والوظيفة والمستأجر تحتاج سياق هوية وسياسة. |
| D02 الهوية والمصادقة | مؤشرات إعداد واسترداد وجلسات وSSO في المصدر والإعدادات. صحة مسار MFA وWebAuthn تتطلب مراجعة أدلة تشغيل موثقة. |
| D03 الجلسات والتوكنات | HAR منقّح وإعدادات وسياسات للأعلام والمدة والإبطال. ادعاء سلامة JWT أو CSRF يحتاج دليل من الكود أو الاختبار الذي قدّمه الفريق. |
| D04 الحقن | إشارات تحليل ساكن في المصدر حسب اللغة والقاعدة. نتيجة النمط تحتاج تقييم مسار البيانات والسياق. |
| D05 المتصفح والعميل | قواعد HTML وHAR الحالية، ثم إشارات JS بحسب المحلل المعتمد. XSS وإعادة التوجيه وpostMessage تحتاج دليل خاص بالحالة. |
| D06 الطلبات الخادمية والملفات | مراجعة سياسات جلب الروابط والرفع والأرشيف والمسارات في الكود والإعدادات. الاستنتاج يعكس اللي مرئي في المصدر. |
| D07 منطق الأعمال | قوائم مراجعة وأدلة يقدّمها مالك النظام ومواصفات السيناريو. الدفع والسباقات والاسترداد تتطلب قرار مراجع. |
| D08 الـAPI | جرد OpenAPI والسياسات والأدلة المستوردة. التفويض والسلوك أثناء التنفيذ يبقوا محتاجين دليل تشغيل مستقل. |
| D09 التشفير والبيانات الحساسة | مراجعة إعدادات ومصدر وHAR منقّح. قيمة سر أو هويتُه الخام تُحجب قبل التقرير. |
| D10 إعدادات HTTP | قواعد الهيدرز وCORS وCSP الموجودة وأدلة ملتقطة محفوظة. DNS والكاش والخادم تحتاج أدلة مناسبة. |
| D11 التبعيات وسلسلة الإمداد | قاعدة بيانات محلية مع lockfile وSBOM عند القبول. provenance والتوقيعات والتبعيات غير المثبتة حالات مستقلة. |
| D12 البنية التحتية وIaC | المصدر وDocker/Kubernetes/Terraform بعد قبول adapter وقواعده. صلاحيات أو حالة حساب سحابي وقت التشغيل تحتاج دليل خارجي. |
| D13 CI/CD والمستودع | تعريفات workflows المرفوعة وقواعد التثبيت والصلاحيات والأسرار. حماية الفرع تحتاج metadata موثقة. |
| D14 التسجيل والأخطاء والرصد | مراجعة كود وإعداد وأدلة أحداث منقّحة. فعالية التنبيه قرار مستقل بأدلة. |
| D15 التوافر والموارد | مراجعة إعدادات الحدود والمهل والأحجام والطوابير. قياس حمل مرصد نفسه ممكن على عيناته، واختبار إجهاد الأهداف خارج خطة المنتج. |
| D16 التصميم غير الآمن | مراجعة معمارية وأذونات وحدود ثقة، بتوقيع مراجع بشري. |
| D17 بروتوكولات الوقت الفعلي | مراجعة مواصفات WebSocket/SSE وتقارير تشخيص قدّمها فريق التطبيق. تقييم بروتوكولي تفاعلي خارج الخطة. |
| D18 تطبيقات الذكاء الاصطناعي | مسار مراجعة منفصل لصلاحيات الأدوات والأدلة والذاكرة ومدخلات الموديل، وتأجيل توسيعه حتى تتوفر fixtures ومراجعة بشرية. |

تسلسل لوحات التغطية **مدعوم → منطبق → اتنفّذ → ظهر دليل → اتراجع**. المقامات من المدخل والسياسة. سَجّل `not_applicable` و`skipped` و`error` و`requires_context` من غير تحويلهم إلى نجاح. الملاحظة نفسها تحتاج موضعًا ومصدرًا وثقة وحالة مراجعة. المطابقة بين كود ولقطة ويب تربط دليلين لنفس الأصل بإثبات ارتباطها، مع بقاء كل دليل قابل للتتبع.

## استراتيجية التقييم

1. Phase 6 سجلت ١٨ حالة اصطناعية و٢٥ قاعدة انطبقت على الأقل مرة، والقياس كان عدد النتائج لكل قاعدة وحالة. استخدمها baseline رجوع، وسجّل بيانات منفصلة بمواقع أدلة ونسخ ملفات ومعرّفات متوقعة قبل تقييم المحللات الجديدة. [تقييم النسخة الحالية](RELEASE.md#التقييم)
2. استخدم OWASP Benchmark للمجموعات المدعومة في تحليل المصدر حسب نوع اللغة والتسميات المرجعية. اختبر مواضع الأدلة والحالات السليمة مع مجموعة محلية ثابتة لأدوات الأسرار والإعدادات وHAR. Juice Shop وWebGoat وNodeGoat وcrAPI وDVWA مرشحات fixtures ومراجعة تدفق المنتج كبيانات محفوظة. PortSwigger Academy مصدر تعليمي. استخدام المواد خارج الترخيص أو تشغيل فحوصات ضد بنية خارجية خارج المسار. [OWASP Benchmark](https://owasp.org/projects/benchmark) · [Juice Shop](https://owasp.org/projects/juice-shop) · [WebGoat](https://owasp.org/projects/webgoat) · [crAPI](https://owasp.org/www-project-crapi/) · [NodeGoat](https://github.com/OWASP/NodeGoat) · [DVWA](https://github.com/digininja/DVWA) · [PortSwigger Academy](https://portswigger.net/web-security)
3. ثبّت split التطوير والقبول حسب المشروع أو اللقطة لمنع تسرب الحالات المتشابهة. وحدة القياس `weakness/rule + artifact + location` بعد التطبيع. سجل TP وFP وFN وTN حسب المجموعة، وprecision وrecall وF1، وFPR لما السلبيات مُعنونة وحجمها كفاية. خلايا بلا مقام تُعرض غير قابلة للقياس. اعرض عائلات نخدمها وحجم العينة وفروق وضع الهوية لما الأدلة تتيح.
4. قارِن ثلاث عمليات على نفس الأدلة. مرصد الحالي، أدوات التحليل مع مسار حتمي، ونفس الأدوات مع إثراء الوكلاء. اعرض حالات اختلاف الدليل والموضع وشرح الإصلاح، وزمن أول نتيجة وp50/p95 والفشل والتكلفة والتوكنات. قبل اختبار الوكلاء ثبّت rubric للشرح بالعربي والإنجليزي (النطاق، الأعداد، الأولوية، الإصلاح، الدليل) وحد أدنى يُسجّل قبل فتح النتائج. كرر الحالات على نفس البيئة وسجل مصدر الاختلاف. مقاييس التقييم تبقى في التوثيق التقني.
